Why PROBE Abstains Instead of Guessing

A challenge page, login wall, or generic shell is uncertainty, not evidence of absence.

19 September 20264 min read

A username checker is under constant pressure to return a simple answer. The web rarely provides one. HTTP 403 can mean a blocked scanner, a private profile, regional policy, or a platform-wide outage. HTTP 200 can be a real profile, a generic application shell, or a polished “user not found” page.

Unknown is a useful result

PROBE separates conclusive decisions from abstentions. A source becomes found or not found only when its status, redirect behavior, title, or body markers provide enough source-specific evidence. Challenges, rate limits, and ambiguous responses remain blocked or unknown.

This lowers headline coverage, but it protects the more important property: a found result should be worth investigating. In the latest 648-control negative set, PROBE produced no observed false positives.

Why generic rules fail

One platform may use 404 for a missing account, another may return 200 with a “user not found” title, and another may redirect existing accounts through login. Applying a universal “200 means found” rule creates false matches. Applying “login redirect means missing” breaks platforms where existing accounts are deliberately gated.

The next coverage gains

The largest abstention cohort is HTTP 403: 149 controls across 53 sources. Four sources produced HTTP 429 controls, while six sources showed challenge titles. These groups can overlap, so they should be treated as measured cohorts rather than added into one source count.

Proxy and browser work will be introduced only where a controlled experiment improves coverage without increasing false positives. The direct request remains the baseline, and every fallback should be recorded as evidence.
