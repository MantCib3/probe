373 active sources: 324 automatic checks and 49 deliberate manual-only links. Results stream live with category and status filters, reason codes, and CSV/JSON export.

Each site has its own rules for response codes, page wording, redirects, and challenge pages. When the evidence is unclear or blocked, PROBE says so instead of guessing.

Case notes, pinned profiles, manual pivots, evidence inspection, downloadable results, and result-reporting are available in the current interface.

Across 947 tests, PROBE was correct in 95.34% of the cases where it gave a clear answer. It reached a clear answer 72.44% of the time and produced no false matches in the test set. We also removed 334 dead or unreliable site definitions.

We are reviewing 32 apparent missed accounts and testing alternative routes for sites that block or limit requests. The current problem groups include 53 sources returning HTTP 403, four returning HTTP 429, and six showing challenge pages. Some sources appear in more than one group.

Run known real and missing usernames on a schedule, watch for changes in site responses, and create a review list when tests go stale. The aim is to catch site changes before users have to report them.

Move long-running scans and usage limits out of a single server process. Add proper job queues, cancellation, shared limits, and short-term result caching before supporting heavier use.

Search a limited list of usernames, follow each job’s progress, and export the combined results. A documented API would provide secure access with clear usage limits and a stable response format.

Collect public details such as profile pictures, biographies, links, and follower counts, with optional screenshots. Browser-based collection would only be used when a normal request cannot reach the page reliably.

Let people suggest new sites, then test each suggestion before adding it. Free and expanded access plans will only be considered once running costs, abuse prevention, and reliability are understood.

Looking for signs that accounts may belong to the same person would be a separate phase, not a small addition to username search. It would need clear rules for consent, data retention, safety, legal review, and human verification before any release.
