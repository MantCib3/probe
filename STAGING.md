# Isolated Render testing

This private repository starts from PROBE commit `0cba21b`. Its test harness is
not deployed to the main production service. Detection, deadlines, username
rules and detection use the production functions. Source and metadata changes
in this repository are staging candidates, not production releases.
The harness bypasses frontend CAPTCHA only for
authenticated, catalog-bound single-source tests; it does not test the public
scan UI, its scheduling, CAPTCHA or scan rate limits.

Deploy the Render Blueprint in [render.yaml](render.yaml) with **Free** compute.
Keep `NODE_ENV=production`, `PROBE_STAGING=1`, and `TRUST_PROXY=1`.
The Blueprint pins Node to `24.11.1`, matching the local baseline runtime.
Runtime files use LF line endings so Windows and Linux byte hashes agree.
`STAGING_PROBE_KEY` is generated by Render; store it only in secret storage and
send it as an `Authorization: Bearer` header, never in a URL or tracked file.
A missing/short key makes staging startup fail. With staging disabled, both
test routes return 404.

- `GET /api/staging-health` returns authenticated runtime hashes and the Render
  commit, region (when available), and provider.
- `POST /api/staging-probe` accepts JSON `{"site":"GitHub","username":"example"}`.
  It allows only automatic catalog entries and validated usernames, not
  arbitrary URLs. The JSON limit is 2 KB and body timeout is five seconds.
- Blocker census mode: the same route accepts
  `{"census":{"url":"https://…","username":"x","method":"GET","variant":"honest"}}`.
  The URL must be HTTPS on a registrable domain of an active catalog source,
  with no port or credentials. Redirects are not followed. It returns only the
  structured signals from [tools/census-observe.js](tools/census-observe.js)
  (status, redirect class, anti-bot vendor fingerprint, title, canonical,
  JSON-LD types, size, hash and username reflection), never the body.
  `variant: "browserlike"` is a diagnostic override. Normal requests currently
  use browser-style headers by default; some source adapters explicitly use
  the PROBE user-agent. Do not describe the default as honestly identified.
  Census requests share the same in-flight and hourly limits. The lab's
  `src/blocker-census.js` drives it; this mode is never ported to production.
- Tests have a global maximum of two in-flight requests and 120 attempts/hour.
  Requests over those limits return 429 with `Retry-After`.
- Results are returned with no-store headers. The harness does not persist
  profile fields, usernames, response bodies or authorization headers.
- Nightly lab view: `POST /api/staging-lab-report` (same bearer key, JSON up to
  256 KB) stores the lab's nightly summary in the separate `probe_lab` schema of
  `DATABASE_URL` (kept in memory if the database is unavailable). `GET /lab`
  shows it behind HTTP Basic auth: any username, password `LAB_VIEW_PASSWORD`.
  Both return 404 unless `PROBE_STAGING=1` and `LAB_VIEW_PASSWORD` is set.
  Ten wrong passwords from one address lock it out for 15 minutes.
- The original `/api/lab-probe` stays disabled in production. Public scans
  still fail closed without a separately configured Turnstile secret.

Run `node --test test/staging-probe.test.js` for harness regressions.
CI separates offline regression/embedded SQL, a required Playwright browser
job, and a dedicated TLS PostgreSQL 17 job. Set `PROBE_REQUIRE_BROWSER=1` or
`PROBE_REQUIRE_POSTGRES=1` to make missing local prerequisites fail rather than
skip the respective test. Embedded SQL does not certify PostgreSQL
client/pooler/concurrency behavior. New CI jobs must actually run before they
count as verified gates; their presence in this checkout is not a pass.

Post-deploy verification accepts `--report <new-file.json>` and retains its
timestamp, expected/observed commit, catalog hash, runtime-code hash, source
counts and failures as a CI artifact. It remains a smoke test, not a public
search browser journey. The runtime hash covers the application code, not just
the existence classifier.

The nightly report view displays completed/degraded/failed/skipped states,
email-delivery health, campaign commit/hashes and evidence age. Reports older
than 36 hours are explicitly stale. A 404 on `/lab` or its upload endpoint is
not a successful report run: verify deployment, `PROBE_STAGING` and the
privately configured `LAB_VIEW_PASSWORD`. Never put that password in reports
or source control. No live view restoration is established by local tests.

Use the hosted baseline runner with a small manifest of existing campaign
controls, and retain the actual runtime hashes and commit in each report.
Set `STAGING_PROBE_KEY` in the local process environment, then run:

```powershell
node tools\run-hosted-baseline.js https://your-service.onrender.com C:\path\manifest.json C:\path\new-report.json
```

The manifest uses a flat `controls` array of `{site, username, expected}` rows;
include label provenance on each row. Limit it to 60 controls or fewer.
Requests are sequential with a minimum ten-second pause (`intervalMs`, default
10000). Do not run multiple campaigns simultaneously against hosted staging.
This bounds test traffic but cannot guarantee isolation from shared Render
outbound IPs. Production block-rate telemetry is not available in this harness;
do not claim it was monitored or run broad production scans as a substitute.
The runner checks every runtime hash and the deployed commit, runs sequentially,
refuses report overwrites, and stops explicitly on HTTP/configuration errors.
Reports belong in the local accuracy lab, not in this repository.
Generated negatives and legacy positives are diagnostic, not certified truth.
Compare the exact same controls locally and remotely close together in time.
Keep transport errors separate from source-level blocks and abstentions.

Render Free services sleep after 15 minutes idle and can take about a minute
to wake. Warm up and authenticate health before timing probes. Free hours are
shared across a workspace; unusual outbound traffic can trigger suspension.
Start with a small sample, not a full-catalog or continuous campaign.
Free hosting measures this service's network conditions, not every production
IP, hosting plan or future deployment. It does not bypass source restrictions.

Do not attach production custom domains, copy production contact/email secrets,
add proxies or browsers, or promote staging changes to production implicitly.

## October 15 UTC milestone

The archive promotion and unrelated-profile redirect bugs were already fixed
in the inherited `0cba21b` commit. Ten integrity regressions passed before this
batch. Historical precision claims already have archive-promotion caveats.

Access diagnosis covers PyPI, Codeberg and Last.fm. Codeberg's documented public
user endpoint returned three positive and three missing responses locally with
an honestly identified PROBE User-Agent. The staging candidate changes only that
source's static User-Agent, not its URL, response rules or access privileges.
PyPI's HTTP 200 client challenge is not a profile. Its documented package APIs
are not substitutes for account existence. Last.fm's official `user.getInfo`
method requires an API key; no key, scraping service or proxy was added.
Neither source is declared permanently unrecoverable.

Metadata changes cover GitHub, Hacker News and GitLab. Reviewed JSON objects are
selected only at the configured root/path with an exact identity key, never by
recursively choosing the richest object. Duplicate matching array entries
abstain from extraction. HN IDs are case-sensitive. Missing/mismatched identity
means no metadata, not a changed existence verdict.

- GitHub: root `login`; avatar, name, bio, location, explicit HTTP(S) blog link,
  creation date and followers from their documented API fields.
- Hacker News: root `id`; `about`, `created`, and HTTP(S) links from that
  account's `about` HTML only. HTML is parsed, never executed. A documented
  Firebase key-range query (`orderBy="$key"`, `startAt="about"`, `endAt="id"`)
  omits the unneeded large `submitted` list. Previously that list could exhaust
  the classification body window and leave unparseable truncated metadata.
  The query retains `id` for identity binding; missing users return `{}`.
- GitLab: unique exact `username` in the returned root array; avatar and name.
  No extra endpoint requests or speculative rich fields.

different-day repeat. Candidate labels in a frozen manifest are not certified.
Retain failed/stale candidates in the original report and record corrections
separately; do not tune rules to turn them into successes.
